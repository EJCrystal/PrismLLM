# 请求日志记录失败阶段与错误信息

请求日志新增 `failure_stage`、`error_message` 和 `upstream_error_code` 三个字段。列表页只展示错误码和阶段，完整错误信息放在“请求详情”弹层中。

## 理由

只有 `error_code` 时，排障需要先知道错误码的语义，也无法区分“模型没有匹配到渠道”和“渠道已选中但上游返回错误”。失败阶段能把问题定位到请求解析、路由、上游调用、流式传输或客户端取消，错误信息则保留网关生成的可读原因。`upstream_error_code` 单独保存上游返回的 `error.code` 或 `error.type`，避免把它和网关错误码混在一起。

请求日志页仍然保持精简：新增字段只在需要时通过详情查看，不把长文本塞进表格。v1 不单独做请求详情路由，弹层足够覆盖单条请求的排查场景，也避免为日志详情引入新的页面状态。

## Consequences

- 失败请求的日志写入开销略有增加，但仍在异步日志队列中完成，不影响数据面响应。
- 错误信息限制为 1000 字符；上游响应正文仍然不落库。
- 历史日志的三个新字段为空，界面显示为“—”。
- `failure_stage` 取值为 `request`、`routing`、`upstream`、`streaming`、`client`。
