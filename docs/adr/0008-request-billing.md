# 单请求计费按渠道与模型单价快照

请求日志增加单条请求费用。价格配置在渠道 + 上游模型维度，单位是每百万 token；费用在日志写入时计算并保存单价快照。

## 理由

同一模型在不同渠道可能有不同结算价，价格不能只挂在模型别名上；未建别名、直连上游模型的请求也需要计费。按渠道 + 上游模型建唯一价格规则，能覆盖别名路由和直连路由。

费用必须在写入日志时确定。价格会调整，甚至渠道会被删除；如果日志读取时再查价格，历史费用会漂移。因此在异步写日志时查价、计算并保存费用与单价快照。

## 口径

- 输入费用：未缓存输入 token × 输入单价。
- 缓存费用：缓存 token × 缓存输入单价；缓存单价为空时按输入单价。
- 输出费用：输出 token × 输出单价。推理 token 已包含在输出 token 中，不重复计费。
- 金额除以 1,000,000，保留 8 位小数，四舍五入。
- 未配置价格、usage 未知或输入/输出 token 缺失时，费用保持为空，不估算、不按 0 处理。
- 价格规则的币种独立；跨币种金额不做汇总。

## Consequences

- 请求日志多出费用与单价快照字段，迁移为 `V6__billing.sql`。
- 改价只影响之后的请求；删除价格不会影响历史费用。
- v1 只做单请求成本展示，不做余额、配额、账单或跨币种汇总。
