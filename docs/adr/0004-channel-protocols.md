# 渠道声明支持的协议

v1 在渠道上保存 `protocols`，取值为 `chat_completions` 和/或 `responses`。数据面按请求路径确定协议，只把请求路由到声明支持该协议的渠道；不在两种协议之间做转换。

## 理由

OpenAI 兼容上游并不都同时实现两种接口。把协议放在渠道上，可以让同一别名在不同协议下选择不同候选，也能在请求日志中直接看出实际使用的协议。

## Consequences

新增渠道默认只启用 `chat_completions`，需要 Responses 时显式勾选。管理面提供手动“探测协议”，不在保存渠道时自动探测，避免隐式请求、token 消耗和限流。别名存在但没有任何支持当前协议的候选时返回 `protocol_not_supported`，而不是静默切到错误的上游。
