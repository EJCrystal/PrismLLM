# 管理台组件库复核

## 结论

| 能力 | 选择 | 原因 |
| --- | --- | --- |
| 游标分页 | 自建 `CursorLoadMore` + 通用游标分页器 | 接口使用 `beforeId` 游标且没有总条数；`vue-awesome-paginate` 一类组件依赖总页数和随机跳页，直接接入会造成重复、漏页或额外全量计数。`@vueuse/core` 的无限滚动会自动触底加载，不符合审计与日志的显式加载需求。 |
| 弹窗 | `@headlessui/vue` Dialog | 成熟、无样式，直接提供焦点锁定、Esc 关闭和可访问语义，适合现有主题系统。 |
| Toast | 保留轻量主题队列 | `vue-toastification` v2 支持 Vue 3，但需要全局插件和独立 CSS。当前 `notify` 从模块直接调用，并与三套主题变量紧耦合，引入插件没有明显收益。 |
| 图标 | 保留按需内联 SVG 包装 | 当前组件只包含实际使用的路径，没有行为逻辑；成熟图标库会扩大依赖并改变整套图标语言，暂不迁移。 |
| 复制按钮 | 保留领域包装 | 底层直接使用浏览器 Clipboard API，并实现非安全上下文降级、成功反馈和无障碍按钮；没有需要替换的复杂 UI 行为。 |
| 密码输入 | 保留领域包装 | 基于原生 input 和单一显隐状态，浏览器已经提供核心能力；外部组件主要会增加主题适配成本。 |
| 表格空态/加载态 | 保留领域组件 | 文案、图标、动作按钮与当前管理台业务和主题绑定，通用表格库无法直接覆盖。 |
