# 调用方密钥访问范围设计

状态：已确认。用户已授权按本设计实施。

## 需求与现状

允许管理员为每把调用方密钥指定可使用的渠道、渠道密钥及对外模型 ID。
只允许一项与允许多项使用同一套规则；未配置访问范围的现有密钥保持现有行为。

目前 `ClientKeyRecord` 和管理 API 只有状态、有效期与额度限制。
`UpstreamModelCatalog` 按对外模型 ID 生成全局候选，`ProxyRoutes` 再执行调度和故障转移。
数据面模型列表也没有按调用方密钥过滤。

本功能解决调用方的数据面访问范围问题，沿用现有单管理员管理面，不增加管理员角色系统。

## 方案比较

| 方案 | 能力与代价 | 建议 |
| --- | --- | --- |
| 固定绑定一个渠道、密钥或模型 | 配置简单，但难以表达多个授权对象，限制故障转移 | 不作为第一版 |
| 三个维度的白名单 | 同维度允许多项，不同维度取交集，能覆盖当前需求 | 推荐 |
| 多条渠道、密钥、模型组合规则 | 能表达模型 M1 只走渠道 A、M2 只走渠道 B；匹配与管理更复杂 | 后续确有需求时再评估 |

推荐白名单方案。它不表达逐模型的不同渠道绑定：允许 A、B 两个渠道和 M1、M2 两个模型时，四种组合均可能获准，实际仍受渠道模型授权约束。

## 术语与规则

- 调用方密钥：网关签发给调用方的凭据。
- 渠道密钥：某个渠道下的静态上游凭据，与 OAuth 订阅账号区分。
- 对外模型 ID：调用请求中的 `model` 值；Gemini 使用 URL 中的模型 ID。
- 访问范围：这把调用方密钥获准使用的渠道、渠道密钥与对外模型 ID。

每个维度具有明确的两种模式：

1. 不限制：使用当前全局配置中满足其他规则的对象。
2. 白名单：只允许名单中的对象。白名单为空表示该维度不允许任何对象。

同维度取并集，不同维度取交集。模型 ID 精确匹配，不支持通配符，也不改写大小写。
保存前去除 ID 首尾空白、去重并校验长度。

渠道密钥必须使用 `(channelId, keyId)` 标识，不能只凭展示名称匹配。
渠道白名单与渠道密钥白名单同时存在时，密钥所属渠道必须在渠道白名单内。
渠道密钥处于白名单模式时，只允许选中的静态密钥，OAuth 账号不参与候选。
渠道密钥处于不限制模式时，保持原有静态密钥与 OAuth 账号的候选行为。

示例：

| 配置 | 结果 |
| --- | --- |
| 渠道 A，其他维度不限制 | 只能通过 A 的原有候选调用模型 |
| 渠道密钥 A/K1，其他维度不限制 | 只能通过 A/K1 调用其支持的模型 |
| 模型 M，其他维度不限制 | 只能调用对外模型 M，可在全局合规候选中选路 |
| 渠道 A、密钥 A/K1、模型 M | 只能通过 A/K1 调用 M |
| 任意维度的白名单为空 | 该密钥没有可用访问范围 |

## 授权与可用性

访问范围是硬性授权边界，冷却兜底、重试、协议转换与故障转移都不能扩大范围。
授权过滤发生在取得上游许可、探测租约和发起上游请求之前。

三个维度均为不限制模式时，保留现有路由和错误语义。
例如模型仅配置在已停用渠道中时，现有目录将其排除，仍返回 `404 model_not_found`。
以下新增的授权及不可用判断用于至少一个维度处于白名单模式的调用方密钥。

一次请求取得调用方密钥及其访问范围快照；本次所有尝试共用该快照。
管理员修改后，后续请求生效，已开始的请求继续使用原快照。

需要区分三类结果：

- 模型或配置对象不存在：保留原有不存在错误语义。
- 对象存在，但不属于该密钥的访问范围：返回 403 与稳定的访问范围错误码，零上游尝试。
- 授权对象存在，但暂时停用、限流或不可达：保留授权范围内的原有 429、503 或上游错误语义。

判断授权时包含已配置但暂不可用的渠道模型与凭据，而不能仅对当前可用候选做过滤。
`configured`、`protocolReachable` 和 `retryAt` 等诊断信息必须按授权范围计算。
授权范围外的可用性、冷却与恢复时间不能决定本次请求的错误或重试提示。

现有 `GET /v1/models`（OpenAI 格式）和 `GET /v1beta/models`（Gemini 格式）共用同一访问范围过滤。
展示的模型必须在授权渠道和授权凭据中存在可用候选；保留现有列表的协议匹配规则。
四种请求协议均须执行授权，Gemini 从 URL 读取模型也不能绕过模型限制。
两个版本的 Gemini 生成请求路径均须覆盖；本功能不新增模型列表路径，也不修改现有响应格式。
搜索请求的内部模型调用沿用已经授权的候选，不重新获得全局候选。

## 存储与模块边界

保留现有模块依赖白名单：

- `prism-quota` 中的调用方密钥记录只保存模式和对象 ID，不依赖渠道或路由实现类型。
- `prism-routing` 通过本模块定义的只读访问范围参数接收 ID，不依赖 `ClientKeyRecord` 或配额模块。
- `prism-app` 负责管理 API 校验，以及调用方访问范围到路由参数的转换。

建议增加三项白名单模式标记，以及渠道、渠道密钥、模型的授权关联表。
不限制模式与关联表为空不能混用；现有记录迁移后全部为不限制模式。
模式和关联记录必须原子写入；读取必须来自同一个数据库快照，可使用单次查询或一致快照事务。
普通 READ COMMITTED 事务中的多次查询不足以保证这一点，不能读到旧模式与新名单的组合。
管理列表批量读取关联，避免逐密钥查询；三个维度均不限制的记录不必查询授权关联。

渠道及静态密钥关联可在目标删除后级联移除，但对应白名单模式保持不变。
因此删除唯一授权目标后，该维度仍为白名单且为空，绝不能变成不限制。
模型授权保存对外模型 ID；删除模型映射后不自动放开授权范围。

调用方密钥删除时清理授权关联。轮换、禁用、重新启用与撤销沿用现有生命周期规则。
轮换保留授权；撤销后的密钥仍不能编辑或轮换。

## 管理 API 与界面

在创建、编辑及读取调用方密钥的 API 中增加访问范围对象，显式传递各维度的模式和名单。

- 创建请求未提供访问范围：三个维度均不限制。
- 更新请求未提供访问范围或传入 null：保留已有范围。
- 更新请求提供完整访问范围对象：原子替换三个维度。
- 清除限制必须显式发送不限制模式，不能依靠省略字段。

上述兼容规则保护现有只更新启用状态或额度的请求，避免意外清除授权。
读响应始终包含完整访问范围，使新界面可以准确显示和编辑。

管理 API 校验渠道、密钥存在及其所属关系，校验模型 ID 在已配置模型映射中存在。
暂时停用的对象可以授权。非法对象或矛盾的渠道、密钥组合不能留下部分更新。
已有配置因目标删除失效时，界面明确显示无授权目标，不自动重置模式或扩大范围。
访问范围修改纳入现有管理操作审计，不记录密钥明文。

调用方密钥创建、编辑表单增加三个配置项，各项可选择不限制或白名单并多选。
选择器只展示管理员可用的名称与 ID，不展示上游凭据明文。
列表以简短摘要展示范围，完整配置在编辑表单查看。
现有启用、删除、轮换与撤销交互保持原有行为。

## 验收与测试

1. 旧记录及旧 API 请求保持原有权限；仅更新状态或额度不会清空授权。
   三个维度均不限制时，模型仅配置在停用渠道的现有 404 行为保持不变。
2. 单渠道、单渠道密钥、单模型和多项交集都能正确允许与拒绝。
3. 403 拒绝时不会发起上游请求，也不留下调用方或上游并发占位。
4. 授权对象不可用时，不回退到范围外对象；普通尝试与冷却兜底都覆盖。
5. 白名单为空、目标被删除、全部停用与协议不支持被正确区分。
6. 四协议请求与两个现有模型列表一致执行授权，两个版本的 Gemini URL 和搜索路径不能绕过。
7. 同一对外模型 ID 对应不同渠道和上游模型名时，仍按对外 ID 授权。
8. 静态密钥白名单排除 OAuth 候选；不限制时保留原有 OAuth 行为。
9. 创建、编辑、轮换、撤销与删除的持久化及管理操作审计正确。
10. 组件测试挂载真实表单，验证多选、回显、保存与状态切换保留授权。

实施顺序：持久化与 API → 路由授权与模型列表 → 管理界面 → 针对性与全量回归。
实现中的 Kotlin 代码提供标准 KDoc；维持现有 ArchUnit 模块边界测试。
在 WSL 原生文件系统的隔离开发检出中运行后端测试，复用已验证的 Java 21、Maven 与 Docker 环境。
前端运行测试、类型检查与构建；后端运行模块测试、PostgreSQL 集成回归及打包。

当前 Windows 工作区中已有用户暂存的前端改动，实施时须保留，不纳入本功能的提交。

## 第一版范围

本轮不新增逐模型的渠道绑定组合、不新增 OAuth 账号白名单、不加入通配模型权限。
不增加管理员角色、多副本协调或配置缓存，也不与全面拆分 `ProxyRoutes` 合并实施。
若需要逐模型绑定或指定 OAuth 账号，应先补充相应规则，再修订本设计。
