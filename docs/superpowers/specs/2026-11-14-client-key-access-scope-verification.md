## 实施取舍及成本

1. 串行实施、逐项独立审阅：避免共享接口冲突；成本是不能并行缩短各实现阶段。
2. Windows 独立工作树编辑、WSL 原生目录测试：复用环境并改善速度；成本是镜像漂移风险，已通过源码差异及资源哈希核对。
3. 复用相同基础提交的后端基线，新功能再验证：减少无变化重复检查；若基础不一致会误用证据，本轮固定提交并另跑全量及修复回归。
4. 将旧迁移版本断言 67 更新为 68：保留全部历史/重复行检查；若版本判断有误可能掩盖迁移差异，独立审阅已核对单行修改。
5. 完整目录行为在应用真实 PostgreSQL 集成测试中验证：不为路由新增数据库/mock依赖；成本是目录纯单测隔离较弱，重要行为均有真实集成覆盖。
6. 密钥维度不限制而授权渠道无凭据时保留 503：将无凭据视为不可用；成本是调用方需区分 503 与真正白名单拒绝的 403。
7. 不可构造的“无可达协议”场景改验授权内转换和原生列表：当前固定注册表覆盖全部协议组合；成本是不可达分支没有动态场景，但原 guard 保留且不新增测试注入接口。
8. 稳定授权码由统一响应头传递，并暴露给 CORS：保持 Messages/Gemini 原生错误体；成本是其客户端需读取响应头，文档与真实请求测试明确覆盖。
9. 错误优先级按设计修正为不存在先返回 404、已配置对象才判 403：解决计划措辞较窄的问题；成本是调用方需按存在性分类错误，候选授权不会扩大。
